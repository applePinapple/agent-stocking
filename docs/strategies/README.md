## 来源规则与本地执行

这些文档是对公开规则的简要整理。采用作者明确发表的某个版本时，会写清作者、参数和变体；同一策略仅改变参数的测试没有另凑为多个策略。来源提供可选方案或未明确边界的，保留为待确认，不增添止损、止盈或成交假设。

原文的卖空信号和卖出已有股票属于不同动作。策略4、7、8的相应来源含多空方向或反手订单；文档注明其中如何退出多仓，但是否改为只做多，仍须用户明确选定。不能由收集资料推定授权卖空或真实交易。

每个候选在回测前都需要按 [策略确认模板](../strategy-template.md) 逐项确认：

1. **标的与数据**：市场、证券类型、区间、周期、数据来源、价格复权、公司行动、成交量单位；筛选范围须采用当时可知的证券名单与财务/市值信息。
2. **指标与信号**：平滑及初始化、完整预热、相等/缺失/零分母边界、连续信号、再次入场与加仓；不能因名称相同就声称与通达信输出一致。
3. **成交规则**：收盘确认和实际成交时点、订单类型、冲突优先级、跳空、涨跌停/停牌等显式交易许可、失败后顺延还是取消、结算、整手及流动性限制。来源中的理想同日收盘是执行假设，不能当作已经获准的本地规则。
4. **资金与费用**：初始资金、每笔/每股仓位、组合分配、现金不足、费用及滑点；均不继承策略1约定，也不套用通用引擎默认值。现金和费用须使用 `Decimal`，保留成交及拒单流水。
5. **期末与审计**：期末持仓估值、不补造平仓；正式报告需保留输入哈希、完整配置、来源与程序版本。

本项目已实现日线通用引擎、策略1专用引擎、策略11/13分批状态机，以及策略14/20共享资金组合执行与选择器。这些模块采用不同的输入和成交约定，不能互相代替。通达信公式兼容性、盘中触发、动态建仓能力及正式批次执行仍须分别核对；参数和执行条件未确认时，`pending` 策略不得产出正式收益。

## 时序与偏差

信号只可读取当时已经完成的数据。任何新实现都须验证：截断到某日和保留全样本时，历史信号一致；改变未来行情不会改变已产生的历史信号与交易。日历型策略须使用当时已公布的交易安排，不用未来行情行数倒算日期；盘中触发单不能事后借当天完整 OHLC 预测阈值或先后路径。

未来数据检验也不能恢复后来已消失的信号。用现存历史指标输出时，仍须单独评估重绘和信号删失偏差；用现存股票或今天的指数成分回测过去，会产生幸存者与样本选择偏差。来源网站的收益数字没有作为本项目结果收录。
