# 策略确认模板

把交易规则写成可唯一执行的条件，再录入程序。未明确的条件保持待确认，不根据经验补全。下面是下一次提交策略时可直接填写的内容。

## 1. 范围与行情

- 策略名称与版本：
- 股票代码、市场与证券类型：
- 回测开始日、结束日，以及指标预热数据范围：
- 周期：日线；如需分钟线或盘中交易，需要扩展引擎后执行。
- 数据来源、导出时间、价格单位、成交量单位：
- 价格复权方式，以及区间内是否存在分红、送转、配股等公司行动：
- 停牌、涨跌停及其他买卖许可如何提供：

## 2. 买入条件

- 通达信原始公式或可逐项判断的文字规则：
- 指标参数、引用周期及样本不足时的处理：
- 用收盘后确认信号，还是盘中触发；初版仅实现前者：
- 空仓时触发后的买入数量：初版为按整手约束尽量全仓。
- 已持仓时再次出现买入信号如何处理：
- 连续多日满足条件时，是只在第一次触发，还是每天产生信号：

## 3. 卖出条件

- 通达信原始公式或可逐项判断的文字规则：
- 卖出触发时点与指标参数：
- 空仓出现卖出信号如何处理：
- 是否存在止损、止盈、持有期限或优先级；初版不推断日内价格路径：
- 初版卖出全部持仓，如需分批卖出须先扩展引擎。

## 4. 冲突与成交

- 同一天同时满足买入、卖出条件时的明确规则：
- 下一日开盘无法成交时，是放弃订单还是继续等待：
- 最后一日生成信号时的处理：没有下一根 K 线时不补造成交。
- `settlement_days`：
- 每手数量 `lot_size`：
- 是否有额外仓位、流动性或成交金额上限：

框架当前使用“收盘决策 → 下一根已有日线开盘尝试执行”的时序。你提供的规则若要求其他时序，先实现并验证相应能力，再给出策略收益；不把不兼容规则自动换成框架默认行为。

## 5. 资金与成本

- 初始资金 `initial_cash`：
- 佣金比例 `commission_rate`：
- 单笔最低佣金 `min_commission`：
- 卖出税费比例 `sell_tax_rate`：
- 买卖过户费比例 `transfer_fee_rate`：
- 滑点基点 `slippage_bps`：

比例使用小数，基点按万分之一计量。这里不填写现行费率示例，以免误当作适用于全部历史时期和证券的默认规则。

## 6. 信号对照与验收

- 至少提供几个应买入、应卖出、不应触发的日期及原因。
- 若策略来自通达信，提供对应参数和输出结果，以核对信号与指标边界。
- 确认最终收益包含持仓估值，报告同时列明已完成交易和期末持仓。
- 确认真实数据的买卖许可来源，不能把缺失值当作“可以成交”。

初版可接入 `signals` 文件：每行是当日收盘后的明确动作，详情见 [数据格式](data-format.md)。信号文件由用户提供时，程序能核对日期及执行时序，但无法证明信号本身未使用未来数据；信号产生过程也应保留和验证。

策略实现仅可读取调用时提供的历史 K 线和组合状态，不得读取完整未来行情。MA、REF、CROSS 等函数名称相同不代表边界行为已经与通达信完全一致；核对前应明确记录本地实现约定。

当前本地指标原语采用以下约定：MA 必须有完整 N 根数据才返回值；REF 向过去偏移，缺失历史返回空值；CROSS 要求前一根 `A <= B` 且当前 `A > B`，首根或任一比较值缺失时不触发。演示均线策略至少等待慢均线周期加一根数据，再判断交叉。
